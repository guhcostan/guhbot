An always-on agent is a loaded gun pointed at your accounts

Everyone is shipping agents that log into your tools and act for you. That is genuinely useful, and it is also a new kind of risk: you are handing a program your sessions, your inbox, and your ability to spend money. Then you make it reachable from your phone, so that anything reachable from the phone is reachable by whoever holds the phone.

Most products answer this with a terms-of-service paragraph. We answered it in the architecture, and the architecture is the part you can read.

Two classes of operation. The mascot shows you which.

Every method the host exposes is declared as one of two things, and the host enforces which one you may call. Not a client check. Not a setting.

person

Both eyes open · a human is present

  • Start a run, send a prompt
  • Resolve an approval
  • Write or replace a secret
  • Create, change or delete an agent

background

One eye open · working alone

  • Read the transcript
  • Check status and health
  • List tools and capabilities
  • See what is waiting on you

parked

Eyes closed · nothing is running

  • Waiting for a schedule
  • Waiting for a webhook
  • Waiting for you to come back

A phone that pairs over the network is always the middle state. It cannot promote itself, and there is no flag that would let it. A stolen phone can read your transcripts; it cannot send a message as you, spend a dollar, or approve its own request.

Files and commands

Reads and writes inside one workspace, never outside it. Paths are checked after resolution, so .. and symlinks do not escape. Commands run without a shell, and a child process never inherits your API keys.

on by default

Any agent you already pay for

Drive Claude Code, Codex or OpenCode as the engine, or point the built-in loop at any OpenAI-compatible endpoint. If you already have a subscription, you do not need a second key.

bring your own

Browser and search

A real Chromium with a throwaway profile. Egress is denied unless you name the hosts, and the check runs on every request, every redirect hop, and the final URL. Cookies are never exposed to the model.

off until you allow hosts

A canvas you can look at

The agent renders HTML you can open, served under its own content security policy in a frame with no same-origin access. Charts, reports, small tools — real output instead of another wall of chat.

sandboxed

MCP tools

stdio, HTTP and SSE. Tool names are namespaced per server so one server cannot impersonate another's tools. A stdio server spawns local code, so it needs an explicit opt-in.

off until you configure a server

Works while you sleep

Scheduled and webhook-triggered automations, with a cron engine that handles DST and does not fire 72 times after your laptop was closed for three days.

built in

macOS Messages

Reads only conversations you listed, one read-only handle, never a copy of the database. Sending always requires approval, and there is no option to turn that off.

off until you name chats

Secrets that stay put

Sealed with AES-256-GCM under a key file that is 0600. Tool execution can read a value; the wire cannot. There is deliberately no secrets.get anywhere in the protocol.

built in

Claims you can check

Each of these is a test in the repository, not a promise in a document. If you can break one, that is a security report.

personA background device cannot resolve an approval
pairingA paired device joins as background even when it asks for person
loopbackThe runtime never binds a network socket
rebindingA browser cannot reach the local API by resolving a hostname to 127.0.0.1
secretsA value never appears in any protocol response
jailA model-supplied path cannot escape the workspace, symlinks included
sandboxA canvas frame cannot reach the host origin
egressAn empty allow list means nothing is reachable at all
